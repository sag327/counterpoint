# Counterpoint contract 1.0.0

Frozen for tickets 01, 04a, 05a and 06a. The four Draft 7 JSON Schemas here define the wire objects. They can be consumed by JavaScript or TypeScript. Validate the semantic constraints below as well. See ../design/counterpoint-agent-handoff.md §§4, 5, 6 and 7. This revision has no browser dependency.

## Engine boundary

reset(world, freshRunId) atomically replaces the entire run, clears clocks, history, queues and generations, and returns the rested snapshot. Use a caller-supplied unique run ID in production and a fixed one for deterministic tests. Within a run, IDs are stable. Topology IDs are unique per kind. Link endpoints must exist and differ. A physical link is the collision domain, with ab traveling from a to b. Display position, pitch and voice are separate configuration keyed by world/node. Link and parameter generations start at zero.

enqueue(command) validates the run, unique command ID, target, value and time and inserts it without advancing. Reject invalid input before mutation. Preserve command insertion order on replay. advanceTo(tMs) returns an immutable ordered array of newly emitted events through tMs inclusive. Initial committed time is unset, permitting t=0 commands. Once advanced, a repeated horizon returns an empty array. Earlier horizons and commands at or before the committed horizon are errors. Reject nonfinite times. Represent queue instants as safe integer microseconds, normalize nonnegative sim ms to nearest tick, ties upward. Use ms on the wire. Compare normalized integer ticks. Durations and cycles are strictly positive, edge delay at least 1 ms. Validate edit ranges in §5.4. Snapshot edits apply prospectively.

Event identity is (runId,eventId). seq starts at 1 and increases by one per emission, eventId is e followed by decimal seq. Transit IDs t1, t2, ... are allocated in launch order. Command IDs and auto trigger IDs are separate namespaces resolved by source. Static topology ID order is ascending ASCII. References to causes use local event IDs in emission order. A launch refers to its accepted activation. An arrival refers to its launch through transitId. This chain preserves multiple roots at a merge. Root ancestry is diagnostic only.

## One instant

1. Apply edits in submission order. A real change increments that setting’s generation. No-op edits emit nothing. Disabling a physical link emits link_changed then conduction_canceled for each live transit on it in numeric transit order. Discard invalidated collisions/arrivals. Restoration allows new launches. Direction-delay edits leave existing transit deadlines intact. ERP edits affect subsequent captures.
2. Process valid interior collisions by time, then lowest pair of numeric transit ordinals. Use §4.6 intersection formula, normalized position from a to b. Use the unrounded intersection to classify interior versus endpoint, normalize its timestamp, and dispatch due interior collisions before arrivals on the same tick. Emit one conduction_collision for both transits, invalidate both arrivals. Recompute earliest valid pair on each affected link. Exact endpoint meetings use the node batch below. No intermediate arrival or sound at an interior collision.
3. Emit external stimulus_attempted in submission order, then due automatic stimulus_attempted by node ID, then conduction_arrived in numeric transit order. Record all attempt/arrival IDs per destination. For each destination in node ID order emit ONE activation or activation_blocked. Source is mixed when causes span source categories. incomingLinkIds is the sorted unique set of arrived physical links. Same-time stimuli alone are a single capture. Incoming links are all excluded from immediately outgoing launches, including mixed-source capture.
4. Determine all outcomes from pre-capture state. An unactivated node captures, otherwise t >= refractoryUntilMs captures. Pre-recovery is 1 when rested, zero before ERP ends, then clamp((t−refractoryUntilMs)/recoveryTailMs,0,1). Capture snapshots ERP, updates last activation and deadline. Block preserves both. No pitched note for block. Launch by source node then link ID, along eligible directions excluding incoming links. Decrement uses pre-capture recovery interval per §4.5. Store departure and computed arrival; never infer delay from geometry. Finalize automatic schedules after outcomes.
5. Each automatic node starts at firstAttemptMs. Accepted capture resets a resettable oscillator to t+cycle. A due automatic attempt always schedules its successor unless the same batch already reset it. Nonresetting foci stay on their original cadence. A cycle edit invalidates the old token and schedules t+newCycle or disables the focus for null. Newly enabled foci default to reset-on-capture if initially absent. Ignore stale tokens. A processing budget fault stops the run, identifies the failed instant and requires reset. Publish only complete timestamp batches.

## Consumers and time contract

readAt(tMs) returns a read-only snapshot after the whole batch at that instant, with runId, worldId, tMs, nodes keyed by ID (lastActivationMs nullable, refractoryUntilMs null at rest, erpMs, recoveryTailMs, recovery, excitable), links keyed by ID (enabled, generation, directional settings), and activeTransits (launch payloads). Valid reads lie within the retained interval and committed horizon. Report unavailable history explicitly. Keep enough history for the presentation cursor. Transit visibility is [departure, terminal event); progress is elapsed/planned travel time, reversed for ba when computing position from a.

Runtime alone maps presentation time to sim time. Let anchorSimMs and anchorAudioSec coincide. Audio time for event t is anchorAudioSec + (t−anchorSimMs) × dilation / 1000. In silent mode use monotonic seconds with the same mapping. Expose presentedMs(), committedThroughMs(), earliestInputMs() and audioSecAt(tMs) for the current segment. For P0 start at 4× with a 25 wall-ms wake and 60 wall-ms lookahead. Advance through the converted horizon. Place live commands at max(committed+one tick, presented+5 wall ms converted to sim ticks rounded upward). At startup enqueue guide commands before first advance. Resetting a running guide creates a fresh run. Record actual command timestamps. UI can draw an immediate neutral gesture mark. Show captures at presentation time. Never read engine-head state to draw earlier frames.

Map each P0 activation to one noteIntent with the same runId, eventId, tMs. Sound owns voice mapping and gain; schedule once per identity. Mute only adjusts gain. Pause stops extending the horizon and lets the bounded committed interval finish, then freezes at the boundary. Resume reanchors there with no replay. Dilation changes switch anchors at a committed boundary, preserving sim continuity. On reset/scene change fence and mute old scheduled audio, clear presentation queues and load a fresh run. On visibility/audio interruption silence the old schedule, freeze at the last committed horizon, expose paused state, and explicitly resume there with a fresh presentation anchor. Record any unpresented interval as a diagnostic. No backlog attacks. Silent playback follows the same protocol.

Any wire or semantic change goes through a lead decision with failing input, affected consumers, new revision and migrated fixtures. Downstream fixtures are under tests/ only. Shipping production must use the actual engine.

# Counterpoint contract 1.1.0

Added for Study No. 2 tickets 11a–11d and amended by the lead decisions of ticket 11e before freeze (design/study-2-spec.md, "Engine contract v1.1"). Contract 1.0.0 above stays valid and its four schema files are unchanged. Contract 1.1.0 ships as world.v1_1, command.v1_1 and event.v1_1 schemas. Each is a strict superset of its 1.0.0 file, so every 1.0.0 document also validates under 1.1.0. noteIntent is unchanged.

## Version and compatibility

readWorld reads a world as 1.1.0 when it declares contractVersion "1.1.0" or carries any 1.1.0 field: world coupling, autonomic or limits; node tissue, audible or restitution; automaticity overdrive or protected; direction entry. contractVersion "1.0.0" declares a 1.0.0 world explicitly: it runs exactly as the same world without the key, and it is rejected if it carries any 1.1.0 field (world.v1_1 accepts the value; this pairing rule is semantic). Any other contractVersion value is rejected. A 1.0.0 world runs the 1.0.0 code paths and emits exactly the 1.0.0 trace. The 1.0.0 fixtures, `ring.json` and both committed evidence files are checked byte for byte in tests/engine-v11.test.js. A 1.0.0 run rejects the ten 1.1.0 commands before mutation, so a 1.0.0 stream always validates under the 1.0.0 event schema. A 1.1.0 world without any mechanism, for example `ring.json` plus contractVersion, has the same dynamics. It only adds the 1.1.0 annotations: diastolicIntervalMs, delayParts and cause.

## World semantics

Tissue defaults to atrial and audible to true. The engine never reads audible: mappers return null for audible false sites (handoff §6.2). Shipped study worlds (12a, 13a–13g) declare tissue on every site; `lintStudyWorld(world)` in src/engine/input.js returns one `{ code: 'MISSING_TISSUE', nodeId, message }` finding per untagged site, and study tests assert it is empty. `limits.maxConcurrentTrains` (integer 1–16, default 4) is part of the world, so a performance replays from its own files. Restitution requires erpMinMs ≤ erpMaxMs = erpMs. Coupling ids are unique, from and to differ, the target must have automaticity, and amplitude lies in 0–1. Autonomic depth lies in 0–0.5 and its targets list sinus and/or nodal at most once each. Overdrive gainPerBeat and warmupFactor lie in 0–1. A link is nodal when either endpoint is nodal. Every new duration is a positive tick, and maxExtra and amplitude may be zero.

## Laws

All laws operate on integer ticks. Each time result is rounded once with Math.round, so half ticks go toward +∞, and the fixtures repeat the same arithmetic.

- §A restitution, computed at capture from pre-capture state: DI = t − previous refractoryUntil, null on first capture. ERP = clamp(round(Emax − A·e^(−DI/τ)), Emin, Emax), and Emax on first capture. With restitution, setNodeERP moves erpMax and shifts erpMin by the same amount. The engine keeps the floor as its offset below erpMax and clamps erpMin to 1 ms only where it is used and reported, so every setNodeERP edit reverses exactly (300 → 100 → 300 restores erpMin 50; at erpMax 100 erpMin reads 1). setRestitution replaces the whole law, including the offset; when it changes the rested ERP it emits parameter_changed restitution and then parameter_changed erpMs with the same commandId.
- §B entry, applied at launch from destination state after every outcome of the batch: nominal = departure + link delay + Slow extra + source decrement. If the destination has been activated and nominal ≥ its refractoryUntil, entry = round(M·e^(−(nominal − refractoryUntil)/τ)). Otherwise entry is 0. Arrival deadlines stay fixed at launch.
- §C overdrive: a capture without the focus's own automatic attempt is driven. If its interval I is below the effective cycle T, S = min(Smax, S + round(g·(T − I))). A capture that includes the focus's own attempt is spontaneous, and S = round(w·S). Every schedule, including resets, due attempts and setAutomaticity, is t + T + S. For sinus-tissue foci only, T = round(cycle × stillness × (1 − 0.2·tone) × (1 + d·sin(2πt/P))) at the scheduling instant. Breath applies only when sinus is a target. The nodal decrement maxExtra is multiplied by (1 − 0.5·tone)(1 + d·sin(2πt/P)) at departure for directions whose source is nodal. Breath applies only when nodal is a target. Positive tone is sympathetic (shorter sinus cycle, less nodal decrement); negative tone is vagal. The breath phase is always sin(2πt/P) of absolute sim time t: setAutonomic never resets it, so a toggled Breath replays exactly from the command log. Worked example (§C oracle): 30 pulses at 500 ms into an 800 ms focus (g 0.06, Smax 450, w 0.6) return after 1250, 1070, 962 and 897.2 ms; 897.2 = 800 + 0.6³ × 450 is exact, no tolerance needed.
- §D coupling, applied after launches and before schedules are committed: for each capture of `from` in emission order, then by coupling id, compute φ = (t − origin)/T. origin is the instant the target's pending cycle began: its last firing, reset or cycle edit, or firstAttempt − cycle before its first attempt. The shift is Δ = round(T·a·sin 2πφ), and next = max(t + 1 tick, pending + Δ). Inputs with φ outside [0, 1), and couplings with a = 0, are ignored and emit nothing. A focus reset in the same batch has origin t and therefore φ = 0. setAutomaticity null on a protected focus lifts the protection (it has no own attempt left that could capture it): after the cycleMs event the engine emits parameter_changed { parameter: 'protected', nodeId, previous: true, value: false } with the same commandId. Restoring automaticity does not restore protection. A protected focus is captured only when its own automatic attempt is among the causes. If an external stimulus or arrival lacks that attempt, the engine emits activation_blocked with cause protected, remainingErpMs ≥ 0 and refractoryUntilMs nullable. A same-instant own attempt merges with external causes as in 1.0.0.
- §F lesion: ablate raises progress from its current value to completeness, in 250 ms steps ending exactly at durationMs. Both directions then use round(delay × (1 + 3p²)). Each step emits parameter_changed (delayMs, cause lesion) per direction whose value changed, then lesion_changed. At completeness 1 the final step disables the link, emitting link_changed with cause lesion, and cancels live transits with cause lesion. A pass at or below the current lesion target is a no-op. A later pass continues from the current progress. A complete lesion (progress 1) stays closed until reset: setLinkEnabled(true) on that link is rejected at enqueue when the command log shows the line complete by the command's instant, that is, when an earlier-enqueued ablate with completeness 1 (the first by time, then submission) has start + durationMs ≤ tMs. Like train admission this is judged from earlier commands only. If enqueue order hides the conflict (the closing ablate was enqueued after the enable), the enable is a no-op when it applies and emits nothing. Ablating an already-disabled link is allowed: it records lesion state and emits the delay steps and lesion_changed as usual, but completion emits no link_changed because the link is already off; at completeness 1 the line is then permanently closed. An incomplete lesion of a disabled link can be re-enabled and conducts with the lesioned delay. An incomplete lesion leaves only the permanent extra delay: there is no "ERP floor on the link" (removed in 11e). setDirectionDelay edits the pre-lesion delay. Its parameter_changed values, readAt delayMs and delayParts.baseMs + lesionMs all report the lesioned delay.
- Stillness (applyAgent stillness): e(t) rises linearly to doseScale over 1500 ms, holds for 2000 ms and falls linearly over 6000 ms. It is applied every 100 ms from the command, ending at 9500 ms. The strongest active envelope wins. Nodal ERP gets + round(600 ms·e), atrial ERP × (1 − 0.2e), and the sinus cycle × (1 + 0.5e). The modifier applies after restitution. Each changed site emits parameter_changed (erpMs or cycleMs, cause agent) in node id order. Other tissues are untouched.
- Slow (applyAgent slow): the level ramps linearly from its current value to doseScale in 30 steps of 100 ms, then persists until reset. Each changed step emits parameter_changed (parameter slowing, value = level, cause agent) per non-nodal link. At launch on a non-nodal link, agent = round(linkDelay × 0.3·level × (1 + max(0, (400 ms − CL)/400 ms))). CL is the source's preceding activation interval, and use dependence is 0 on its first activation.

## Commands

All 1.1.0 commands require a 1.1.0 world. Edit ranges extend §5.4:

- stimulateTrain { nodeId, startMs ≥ tMs, cycleMs 150–10000, count 1–64, label ≤ 120 chars }: pulse k (1-based) is stimulus_attempted at startMs + (k−1)·cycleMs with triggerId `<commandId>#<k>`. Pulses enter the stimulus phase in submission order alongside stimulate commands. After the last pulse, train_completed { commandId, delivered } closes that batch. A train holds one pending agenda item at a time.
- cancelTrain { trainId }: the train is named by its own commandId, because commandId is taken by the cancel itself. Pulses at or after the cancel instant are not delivered. If the train has not closed yet, the cancel batch ends with train_completed { commandId and trainId = the train's commandId, delivered = pulses already emitted (0 if it had not started), count, cancelled: true }. Cancelling a train that already completed or was already cancelled emits nothing. A train therefore closes exactly once.
- Concurrent trains: at most the world's limits.maxConcurrentTrains (default 4) may have overlapping pulse windows. Overlap is computed from previously enqueued commands only (a window ends before an earlier-enqueued cancel), never from the horizon, so a command log is accepted the same way live and on replay. The engine option maxConcurrentTrains (default 16) is only a host cap: reset refuses a 1.1.0 world whose limit (declared or default) exceeds it, so a host never admits differently from what the world says.
- setAutonomic { value: { breathPeriodMs > 0, depth 0–0.5, targets ⊆ [sinus, nodal] } | null }: the live Breath toggle. It replaces the world's autonomic prospectively (pending attempts keep their times) and emits parameter_changed { parameter: 'autonomic', previous, value } with targets in canonical order (sinus, nodal). An equal value is a no-op.
- setTone { value −1..1 }, applyAgent { agent stillness | slow, doseScale (0, 2] }, ablate { target linkId, durationMs 1–60000, completeness (0, 1] }, setCoupling { couplingId, value 0–1 }, setRestitution { nodeId, erpMaxMs 50–1000, amplitudeMs 0–1000, tauMs 10–1000, erpMinMs 10–erpMax }, setDecrement and setEntry { linkId, direction, maxExtraMs 0–300, tauMs 10–1000 }.

## Events

1.1.0 runs add diastolicIntervalMs to every activation and delayParts { baseMs, sourceMs, entryMs, lesionMs, agentMs } to every conduction_launched. The parts sum exactly to arrival − departure in integer ticks; summed as ms floats the result may differ from arrivalMs − departureMs by rounding, so consumers should convert each part to ticks (round(ms × 1000)) before adding. They also add cause to every parameter_changed and link_changed: command, lesion or agent. parameter_changed gains the parameters restitution, decrement, entry, coupling, tone, slowing, autonomic and protected. Each target, parameter pair has its own generation counter. erpMs and cycleMs report agent-modified values. New event types are phase_modulated { nodeId, couplingId, sourceActivationId, phase, shiftMs = Δ before the t + 1 tick floor, nextAttemptMs }, lesion_changed { linkId, progress, completeness } and train_completed { commandId, trainId, delivered, count, cancelled }. conduction_canceled cause adds lesion.

## One instant, additions

1. Edits apply in submission order before collisions. This includes setTone, setAutonomic, cancelTrain, applyAgent and ablate registrations, and the derived Stillness, Slow and lesion steps, which take their command's submission position.
2. External stimulus attempts (stimulate commands and train pulses) in submission order, then automatic attempts and arrivals as in 1.0.0.
3. Outcomes, with §A restitution and §C suppression from pre-capture state.
4. Launches, with §B entry from post-outcome destination state.
5. The 1.0.0 post-launch collision drain.
6. Schedules planned: reset and due foci get t + T + S.
7. §D modulation on the planned or pending attempt.
8. Schedules committed.
9. train_completed, in the order the trains closed: cancellations (edit phase, submission order), then completions (stimulus phase).

readAt for 1.1.0 runs adds node restitution and suppressionMs (null without overdrive), direction entry and link lesion { progress, completeness }. erpMs is the rested ERP: erpMax under restitution, with any agent modifier.

## Model notes and open items

Arrival deadlines are fixed at launch, so a later capture of the destination does not move a planned arrival (§B). The §F "ERP floor on the link" was removed from contract 1.1.0 by lead decision (11e): the spec gave neither a value nor a rule, links have no refractoriness in this graph model, and no oracle needs it. If Ostinato (13c) later wants a rate-dependent gap, model it as a silent `audible: false` gap site whose ERP the lesion raises (§E), not as a link rule.
