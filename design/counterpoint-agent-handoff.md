# COUNTERPOINT
## An instrument made of electrophysiology
### Product vision, artistic direction, technical specification, and implementation handoff

**Status:** Implementation brief / pre-prototype · **Target:** Study No. 1, v0.1 · **Audience:** Coding agents, creative technologists, audio developers, simulation engineers, and design agents · **Authority:** This document captures the agreed creative direction; numerical defaults and architectural choices are proposed starting points, not clinical validation.

> The heart does not provide a soundtrack. It provides the rules by which a composition comes into existence.

---

## 0. Read this first — master brief for the implementation agent

Build **Counterpoint**, a beautiful, interactive, browser-based generative audiovisual instrument whose rhythms arise from a simulation of electrically excitable tissue. The user observes a living sculpture of light and sound, touches or changes it, and discovers that electrical phenomena such as sequential conduction, refractoriness, unidirectional block, reentry, and independent automaticity are also musical phenomena.

This is **an artwork first, an instrument second, and an educational electrophysiology simulator third**. It is not a clinical simulator, an ECG teaching dashboard, a heartbeat visualizer, a conventional synthesizer, or a recording-based sonification project.

The creator is a cardiac electrophysiologist with a particular interest in the temporal relationships among intracardiac electrograms and their analogy to musical counterpoint. Scientific credibility matters: rhythms must be generated by an explicit electrophysiologic model, not by canned animations or prerecorded musical sequences labeled as arrhythmias. Musical quality matters equally. Avoid a collection of bleeps or a generic sci-fi particle demo.

Deliver a playable, polished vertical slice first. The first complete experience must let a person start from silence, excite a network, hear a transient phrase, induce self-sustaining reentry through a valid coupling interval, perturb it, and terminate it. The application should also have an immediately beautiful, self-running initial scene. Implement a second and third substrate only after that core loop works.

**Primary deliverable:** A self-contained `counterpoint.html` that runs locally in a modern desktop browser, requires no server or installation, and produces its own audio and graphics. Keep maintainable source files and tests in the repository as well. The single-file release must not load fonts, sound samples, scripts, analytics, or assets from external services. Mobile browser support is important, but opening a downloaded local HTML file on a phone is not uniformly supported; also verify the app over a simple static HTTP server.

**Do not ask the creator to resolve routine implementation decisions.** Make reversible, documented choices, test them, and surface important artistic tradeoffs with working comparisons. Do not spend the first iteration on accounts, backend infrastructure, frameworks, elaborate menus, marketing, or a large library of arrhythmias. Do not claim to have listened to audio if you only inspected generated signals or code. Do not claim that clinical phenomena are supported unless the underlying event behavior is tested.

## 1. Creative north star

### 1.1 Origin and intent

Intracardiac electrogram channels resemble staves in a musical score. A discrete electrogram has meaning through its temporal relationship to other electrograms. Different chambers and recording sites resemble instrumental voices. Conduction creates order and expectation; reentry creates repeating motifs; block creates absence; independent automatic foci create counterpoint.

The project combines two philosophies:

- **Discover the music:** reveal temporal and state relationships that already exist in electrophysiology. Do not impose an arbitrary rhythm on them.
- **Create a living musical system:** build a substrate that can generate behavior that neither the creator nor the listener has explicitly composed.

The preferred implementation is a **synthetic, interactive electrophysiologic engine**, not the import or playback of entire EP studies. Real clinical recordings contain long periods with little artistic interest and create unnecessary data-handling complexity. No patient recordings, PHI, or external clinical datasets are needed.

### 1.2 Aesthetic decisions already made

- Ethereal, contemplative, delicate, luminous, organic, spacious, almost hypnotic.
- Geometric and rigorous underneath; not overtly anatomical or medical in presentation.
- Predominantly acoustic-inspired instrumentation with restrained electronic textures.
- Dark, near-black environment with fine filaments, slowly fading traces, and restrained warm gold / cool blue light.
- The default experience is the **observer**: beautiful without input. The **performer** is revealed by touching and pacing. The **architect** is a later, deeper creative layer.
- Three presentation concepts: **Chamber**, **Atmosphere**, and **Minimalism** (musical palettes), eventually multiple visual modes (Network, Score, Orbit, Field).
- Working title: **Counterpoint**. First public-facing prototype: **Study No. 1**. The names are creative decisions, not a trademark clearance.

### 1.3 Non-negotiable principles

1. **Physiology determines note onsets.** Preserve relative activation times, allowing only a uniform, user-controlled time scaling. No beat-grid quantization, hidden swing, random rhythmic humanization, or backing beat.
2. **Music determines the vocabulary.** Pitch, instrument, tuning, envelopes, and harmonic context are artistic mappings; distinguish them from biological facts.
3. **Light expresses electrical state.** Activation, propagation, refractoriness, recovery, collision, and block should be meaningfully distinct.
4. **Interaction changes the electrical substrate.** Touching a node attempts stimulation; it is not a direct note trigger. A failed stimulus is a valid and meaningful outcome.
5. **Beauty precedes explanation.** Provide a hidden or secondary laboratory and optional labels, but never require the user to understand EP to enjoy the default experience.
6. **One source of truth.** Audio, graphics, logs, and derived electrograms all consume the same authoritative simulation events and model state.
7. **Emergence rather than scripts.** Presets configure parameters, topology, and initial conditions. They do not replay hardcoded arrhythmia patterns or musical phrases. Guided demonstrations may schedule explicitly labeled pacing stimuli, not fabricated activation events.
8. **Silence is music.** Do not conceal a blocked response with a compensatory note or an independent background soundtrack. Reverberation from actual activations is fine.

### 1.4 Experience to avoid

No monitor-green ECGs by default, stock anatomical hearts, neon cyberpunk interfaces, busy starfields, excessive bloom, full-screen explanatory copy, obligatory tutorials, drum loops, metronomes, stock EDM arpeggiators, arbitrary note triggers, fake physiological labels, or automatic chord changes unrelated to the design. Avoid equating disease with dissonance or implying that a beautiful or consonant rhythm is healthy.

## 2. Product experience and scope

### 2.1 Opening sequence

The app opens into a quiet near-black canvas. A sculptural network of approximately 6–8 luminous nodes and fine curving filaments is centered with generous negative space. The title and subtitle are modest. A clear **Begin / Enable sound** action satisfies browser audio policies. After this action, the artwork starts; no registration, loading screen, or tutorial.

Default world: **Conduction**, with a stable automatic source and a restrained ascending/descending activation motif. A user can simply watch and listen. Selecting **Circulation** opens a ring with a short, optional induction demonstration; **Duality** offers independent voices. These are scenes generated by the same engine, not separate applications.

The first engineering vertical slice is Circulation, even though Conduction is the preferred opening world once all three are implemented. If only Circulation is ready, open there instead, offering a quiet ring and a one-touch guided induction option. Do not present nonfunctional navigation.

### 2.2 Core user journey

1. Press Begin; the network comes to life with its own sound.
2. Touch a node: light responds immediately to the gesture; if electrically excitable, the node activates and its wavefront travels through the substrate, producing notes.
3. Touch it prematurely: the wave may block or delay, revealing electrical memory.
4. Explore Circulation: an isolated impulse runs around the ring in both directions, collides, and fades. A second, appropriately timed impulse blocks in one direction and starts an enduring rotating phrase.
5. Perturb the ring with another impulse; hear a reset or collision when permitted by the model.
6. Cut or disable a connection in the performer/lab control: circulating activity ceases when it reaches the break, and the notes decay into silence.
7. Restore/reset the substrate, switch musical palettes, vary time dilation, or explore Duality without reading medical documentation.

### 2.3 Modes and control hierarchy

| Level | Interface | Required behavior |
|---|---|---|
| Observer | Main canvas, title, scene selection, Begin/Pause, sound | Self-running or readily seeded compositions; no required technical knowledge |
| Performer | Tap node, optional hold-to-pace toggle, speed, palette, restore/reset | Meaningful control over electrical behavior; unobtrusive controls |
| Laboratory | Collapsible inspector or drawer | Numerical parameters, event log, timing trace, reset, reproducible protocols, diagnostic sound/visual controls |
| Architect | Later explicit editing mode | Add/remove nodes and edges, edit automaticity, refractory period, conduction delay, directionality; not required for first release |

Do not use editing gestures that interfere with casual tapping. On desktop and mobile, an explicit Edit / Cut mode or an accessible list of connections is preferable to requiring precise strokes on thin lines. Hold-to-pace must be opt-in or clearly indicated, cancel on pointer release/cancel, and never leave an uncontrolled pacing stream running.

### 2.4 Minimum scope and release boundaries

| Priority | Functionality |
|---|---|
| P0 vertical slice | Shared event engine, symmetric bidirectional ring with conditioning/induction, actual sustained reentry, single-node stimulation, ring interruption, reset, real-time synthesized music, visually expressive propagation/recovery, sound enable/pause/mute, uniform time dilation, local single-file build, core deterministic tests |
| P1 prototype | Conduction and Duality scenes; Chamber/Atmosphere/Minimalism palettes; lab inspector, event timeline and induction protocol; accessible touch/keyboard controls; independent master volume; persistence of nonclinical preferences; mobile verification |
| P2 refinement | Richer instrument synthesis, alternate Score/Orbit views, simple pacing controls, physiological restitution refinement, explicit editable connections, export event data and shareable presets |
| Later | Continuous excitable-medium Field view, fibrillation, advanced entrainment demonstrations, editable network sandbox, recording/export of audiovisual performances, optional sound samples, spatial audio installation, public hosting |

Ship P0 independently. P1 is the intended v0.1 complete prototype; P2 and later must not delay it. A visually polished one-scene prototype is preferable to a sprawling broken multi-scene demo.

## 3. Architecture and repository guidance

### 3.1 System design

```text
                   User gestures / guided pacing protocol
                                   │
                                   ▼
             Input command queue (simulation timestamps)
                                   │
                                   ▼
     World definition ─────► Deterministic EP event engine
     topology, parameters       state, queue, propagation
                                   │
                          accepted/blocked events
                          conduction/collision events
                                   │
                       Immutable event stream + state
                 ┌─────────────────┼──────────────────┐
                 ▼                 ▼                  ▼
           Music mapping       Visual renderer      Lab / score
                 │                 │                  │
           Web Audio          Canvas / GPU      Logs / derived traces
                 └──── shared clock & time scale ────┘
```

Keep the engine entirely independent of browser APIs and wall-clock time. It must run in deterministic headless tests. The browser orchestrator translates wall time, UI commands and audio scheduling to simulation time. The audio engine must not change biological state. The renderer must not infer biological state from note playback.

### 3.2 Recommended technology choices

- TypeScript or modern JavaScript ES modules for source; TypeScript preferred if the agent can bundle without increasing complexity. If a dependency-free JS implementation better supports rapid iteration, use JSDoc types and tests. Do not create both full implementations.
- Canvas 2D for P0/P1; sufficient for small graphs, rich radial glows, particles, layered trails and curved filaments. WebGL or a GPU pipeline is an optional later optimization, not a prerequisite for beauty.
- Web Audio API for original algorithmic synthesis, AudioParam scheduling, shared reverb, panning and master gain. No remote samples or third-party audio libraries in the first distribution.
- Semantic HTML/CSS for controls and accessibility. Avoid implementing essential controls solely in Canvas.
- A minimal local build script/bundler that inlines assets into one HTML file. Use a normal static dev server for development if desired. Local Node tooling is allowed; the distributed HTML must run without it.
- No network requests, account creation, database, telemetry, or patient data. Optional local preferences are nonclinical. No service worker is required for P0/P1.

## 4. Electrophysiologic simulation specification

### 4.1 Model boundaries

Use a graph of lumped, electrically excitable elements. Each node represents a conceptual tissue region or recording site, not necessarily a literal cell. Edges represent conduction paths, not anatomical measurements. Time is in simulated milliseconds. This is a phenomenological activation/recovery model, not an ionic membrane model, bidomain solver, or clinical decision support tool.

An accepted activation makes the node temporarily refractory, may reset automaticity, and launches propagating impulses into eligible connections. Incoming stimuli during the effective refractory period block. Conduction time can depend on activation history. Reentry should arise from return of an impulse to excitable tissue, not from a timer that repeats the ring.

For initial implementation, separate **effective refractory period (ERP)**, which determines whether activation is accepted, from **visual/musical recovery**, which is a continuous artistically mapped state. Do not accidentally introduce a second biological threshold by using the visual glow to determine capture.

### 4.2 Suggested data model

The following is illustrative TypeScript-style pseudocode. Exact interfaces can vary, but preserve their semantics and units. Use stable IDs and explicit version tokens for canceled future events.

```ts
type SimMs = number;
type NodeId = string;
type LinkId = string;
type WorldId = 'circulation' | 'conduction' | 'duality';

type NodeSpec = {
  id: NodeId;
  position: {x: number; y: number};  // normalized coordinates, visual only
  label: string;
  erpMs: number;
  recoveryTailMs: number;           // post-ERP gradual artistic recovery
  automaticity?: { cycleMs: number; resetOnCapture: boolean };
  voiceId: string;                  // descriptive role, not engine behavior
};

type NodeState = {
  lastActivationMs: SimMs | null;   // null = rested
  refractoryUntilMs: SimMs;
  activationCount: number;
  pacemakerGeneration: number;
};

type DirectionSpec = {
  enabled: boolean;
  baseDelayMs: number;
  decrement?: { maxExtraMs: number; tauMs: number };
};

type LinkSpec = {
  id: LinkId;
  a: NodeId;
  b: NodeId;
  ab: DirectionSpec;
  ba: DirectionSpec;
  // Treat one undirected physical link as one collision domain.
};

type LinkState = { enabled: boolean; generation: number };

type Arrival = {
  id: string;
  atMs: SimMs;
  nodeId: NodeId;
  source: 'stimulus' | 'automaticity' | 'conduction';
  fromNodeId?: NodeId;
  linkId?: LinkId;
  transitId?: string;
  token?: number;
  rootId: string;                  // wave ancestry for inspection only
};
```

Maintain a separate transit object for each traveling impulse with `id`, `linkId`, `from`, `to`, `departureMs`, `arrivalMs`, `linkGeneration`, and `status` (active, canceled, arrived, collided). Use `rootId` for tracing but never block reentry by marking a root ID as already visited; a circulating wave must be able to activate the same node again when recovered.

### 4.3 Engine commands and outputs

Commands (input events):

```ts
stimulate(nodeId, atMs, strength?);  // strength is optional; P0 fixed suprathreshold
setAutomaticity(nodeId, cycleMs | null, atMs);
setLinkEnabled(linkId, enabled, atMs);
setNodeERP(nodeId, erpMs, atMs);
setDirectionDelay(linkId, direction, delayMs, atMs);
reset(world, seed?);
advanceTo(simTimeMs);               // emits all due events, never consults real time
```

Core output event types (all include world/run ID, unique sequence ID and `tMs`):

| Event | Key payload / interpretation |
|---|---|
| `stimulus_attempted` | Target node, source, protocol/pacing identity if relevant |
| `activation` | Node, source, incoming link(s), prior activation time, preceding interval, ERP at activation, pre-activation recovery, effective outgoing delays if useful |
| `activation_blocked` | Node, source, cause (`refractory`, etc.), remaining ERP; no normal note |
| `conduction_launched` | Transit ID, endpoints, direction, start and planned arrival times |
| `conduction_arrived` | Transit ID and receiving node; distinct from successful node activation |
| `conduction_collision` | Involved transit IDs, link, collision time and normalized position |
| `conduction_canceled` | Transit ID, cause (cut/reset/etc.), position at cancellation if available |
| `link_changed` / `parameter_changed` | Affected IDs, previous/new value and version |

Derived read-only state: node recovery at arbitrary simulation time, active transits, recently emitted events, topology snapshot, and history for lab display. The engine may stream events by callback or return arrays from `advanceTo`, but must support headless test assertions without an audio context or renderer.

### 4.4 Activation and recovery

Let `t` be arrival time and `last` the last successful activation. An arrival is accepted if `last` is null or `t >= refractoryUntil`. On success, compute pre-activation state before overwriting `last`, then set `last = t` and `refractoryUntil = t + ERP_snapshot`. Update ERP via parameter changes prospectively: an ongoing refractory interval remains as established at the previous activation, unless a later explicit model option says otherwise.

For visual and timbral recovery, use an easily explained phenomenological curve:

```text
if never activated: r = 1
else if t < refractoryUntil: r = 0
else: r = clamp((t - refractoryUntil) / recoveryTailMs, 0, 1)
```

A smoothstep of `r` can be used visually. This intentionally depicts relative recovery after ERP; it is not a measurement of membrane potential or restitution. At exactly ERP, activation is legal but may be musically muted. Use a separate short activation-flash envelope so that a newly activated refractory node can bloom briefly, then dim and gradually regain receptivity.

### 4.5 Conduction and decrement

For a successful activation at node `i`, launch an impulse along each enabled eligible outgoing direction. Fixed delay is the base case. Use a simple optional decremental model on selected outgoing directions (particularly AV nodal exit in Conduction):

```text
recoveryInterval = max(0, t - priorRefractoryUntil)
extraDelay = maxExtraMs × exp(-recoveryInterval / tauMs)
travelTime = baseDelayMs + extraDelay
```

A fully rested node has zero extra delay. `priorRefractoryUntil` is the pre-activation value. Store the computed travel time when launched; future parameter changes do not retroactively alter a transit. This captures the qualitative idea of slower conduction after short recovery; the function and values are illustrative, not a validated AV nodal restitution curve.

Prevent immediate reflection into a physical link from which an activation just arrived. This is an explicit graph-model approximation to the refractory wake of a propagating wavefront. If several arrivals coalesce at a node, exclude all incoming links from outgoing launches. Do not globally prohibit revisiting an edge or node at a later time. A fresh external stimulus at a recovered node is allowed to launch in every eligible direction. Document that this simplified rule limits fidelity for some real electrophysiologic responses.

### 4.6 Bidirectional links and collisions

A bidirectional physical link must be modeled as two directional conduction permissions sharing a physical path. If opposing wavefronts are in flight simultaneously on the same link, they should annihilate rather than pass through each other.

For a normalized path coordinate `x ∈ [0,1]`, a wave from A to B departing at `sA` with travel time `dA` has `xA(t)=(t-sA)/dA`. A wave from B to A departing at `sB` with travel time `dB` has `xB(t)=1-(t-sB)/dB`. If their active time intervals overlap, solve:

```text
tCollision = (1 + sA/dA + sB/dB) / (1/dA + 1/dB)
xCollision = (tCollision - sA) / dA
```

Accept the collision only when it lies within both valid transits. Schedule a collision event, invalidate both arrival events using transit IDs/tokens, and retain the transits for visual display until the actual collision time. If a link is cut before a scheduled collision, invalidate the collision and cancel both affected transits. If several candidates exist, select the earliest valid opposing pair, reevaluate on invalidation, and never let a wave collide twice. P0 may simplify to at most one in-flight wave per direction **only if the restriction is explicit, tested, and the supplied presets cannot violate it**; the preferred approach is to support multiple waves and deterministic earliest collisions.

When two arrivals reach the same node at exactly the same simulation timestamp, batch them and accept at most one activation if excitable. Merge incoming links, emit one note, and do not re-launch along those incoming links. This makes a symmetric eight-node ring terminate at the opposite node without requiring a fictitious continuing wave. A collision exactly at an endpoint can be handled by this same deterministic node rule; document the convention.

For P0, do not model distributed refractory tissue within each link. A node-only ERP plus collision and no-immediate-reflection rules are sufficient for the designed demonstrations. Do not advertise this as a faithful continuous excitable-medium simulation.

### 4.7 Event ordering and causality

Use a stable min-heap ordered by `(tMs, eventPriority, sequenceId)` or a simpler ordered queue if the graph is small. Pick a consistent timestamp precision (e.g. integer microseconds internally or floating-point milliseconds with explicit normalization), and use it for batching and tests. Every conduction delay must be strictly positive (suggest minimum 1 ms) to prevent infinite zero-time cascades.

At each timestamp:

1. Apply topology and parameter commands scheduled for this timestamp (cuts invalidate transits immediately).
2. Resolve due valid mid-link collisions; discard stale events by version/token.
3. Collect all valid due arrivals, stimuli and automaticity attempts by receiving node. Emit stimulus and arrival events even if the receiving node blocks. Process each node once for accepted activation; coalesce simultaneous incoming directions.
4. Snapshot relevant pre-activation states, update accepted nodes, then launch outgoing transits. New positive-delay events are inserted into the queue. Do not use node iteration order as a hidden physiological variable.
5. Schedule future automaticity attempts as needed; output stable event ordering.

Automatic foci: use a generation token to invalidate pending pacemaker events when an accepted activation resets the pacemaker. For non-resetting independent foci, use scheduled cycle events unaffected by unrelated activations. If an automaticity attempt occurs during refractoriness, block it and schedule the next attempt, rather than allowing the oscillator to disappear. Avoid scheduling two future attempts after a simultaneous external capture and automatic beat. Keep phase-reset rules explicit; biological automaticity is simplified.

A topology cut invalidates ongoing conduction on that physical link and future launches; it does not erase previously activated nodes or other pending wavefronts. Restoring a link allows future propagation, not resurrection of canceled impulses. Changing conduction delay affects subsequent launches. Reset is a separate operation that clears events, transits, histories, automaticity tokens, and run ID.

### 4.8 Safety limits and deterministic debugging

This is an artistic simulation, but invalid inputs must not hang the browser or overload audio. Validate parameter ranges, node/link counts, event time monotonicity and finite values. Use an event-processing budget per advancement (e.g. 10,000 events; tune it) and pause/report an explicit simulation fault rather than silently dropping activations. Bound the number of retained historical events; do not cap valid physiological events merely to reduce sound. Audio polyphony limits belong in the audio engine, and any voice stealing is disclosed in diagnostics.

Support seeded pseudorandomness if later worlds use variability. P0/P1 deterministic presets should not require random physiological inputs. Decorative particles may be deterministic or seeded but may not change events. Given the same world and timestamped commands, the headless engine must emit the same activation history regardless of frame rate, wall-clock speed or rendering settings.

## 5. Reference electrophysiologic worlds and deterministic protocols

These are synthetic starting parameters designed to produce musically and scientifically intelligible behaviors. They are not measurements of a patient's tissue, clinical recommendations, or validated physiological ranges. All times below are simulated milliseconds, before playback dilation. Agents must verify the expected behavior using the actual implemented engine rather than copying the expected activation history into the application.

### 5.1 Circulation — first engineering vertical slice

**Purpose:** Demonstrate the transition from a transient excitation to self-sustaining reentry. A quiet ring is the initial condition; a successful induction becomes a living repeating phrase. This should be the artistic centerpiece.

Topology: eight nodes `R0` through `R7`, indexed clockwise. Link `L_i` joins `R_i` to `R_(i+1 mod 8)`. All links bidirectional and enabled, with 60 ms delay in either direction. No automaticity. No decrement in this reference case. Set R0 ERP to 180 ms, R1 to 300 ms, R7 to 200 ms, R2–R6 to 220 ms. Set recovery tail to 120 ms on all nodes. The deliberately asymmetric refractory periods create a window for unidirectional block. The total circuit traversal time is 480 ms, exceeding each ERP.

```text
                 R0 (stimulus)
              /                 \
           R7                     R1 (long ERP)
           |                       |
           R6                     R2
           |                       |
           R5                     R3
              \                 /
                      R4
```

**Protocol A: single stimulus.** Fresh reset; stimulate R0 at t=0. Expected accepted activations:

| t (ms) | nodes |
|---:|---|
| 0 | R0 |
| 60 | R1, R7 |
| 120 | R2, R6 |
| 180 | R3, R5 |
| 240 | R4 (one merged activation) |

The waves meet at R4; no sustained circulation remains. After the last activation, audio tails can decay naturally. Total accepted activations = 8. A stimulus at R0 at t=100 is blocked (ERP 180 ms); no additional accepted activations result.

**Protocol B: induction.** Fresh reset. Stimulate R0 at t=0 (S1), then R0 at t=240 (S2). S2 reaches R1 at t=300, only 240 ms after R1 last activated; R1 is refractory until t=360, so it blocks. S2 also reaches R7 at t=300, 240 ms after R7 last activated; R7 has recovered beyond ERP and conducts. The surviving wave traverses the ring counterclockwise.

| t (ms) | S2-derived event |
|---:|---|
| 240 | R0 accepts S2; the S1 wavefronts also meet at R4 |
| 300 | R1 blocks; R7 activates |
| 360 | R6 activates |
| 420 | R5 activates |
| 480 | R4 activates |
| 540 | R3 activates |
| 600 | R2 activates |
| 660 | R1 activates |
| 720 | R0 activates again — one full revolution since S2 |
| 780 | R7 activates again |
| 840 onward | Repetition emerges from propagation, with TCL = 480 ms |

For the reference engine with the described parameters and assumptions, coupling intervals `[220, 300)` ms should permit counterclockwise induction from this S1 initial condition; the lower boundary depends on equality at ERP. Verify the exact interval with a deterministic sweep rather than relying on this analytic prediction. Shorter intervals can block at R0 or elsewhere, and at longer intervals both directions may conduct. A guided button may schedule S1 and S2 with a 240 ms coupling interval. It may not schedule the downstream activations directly. Use a reset or clearly state the need for a rested substrate before starting the reference protocol. Manual induction remains possible; the recommended slow playback makes the interval easier to time.

**Protocol C: terminate.** After stable circulation, disable any link at a chosen time (e.g. L4 at 1000 ms). Existing activity must cease within one TCL of the cut in this single-wave reference configuration. If the wave is already on the cut link, cancel it at that instant. If it has passed, it continues until reaching the break. Restore the link: no activity returns until a new impulse is introduced. The visual sculpture should show an interruption in the filament rather than the entire ring vanishing.

**Protocol D: perturb.** During stable circulation, introduce extrastimuli at varying sites/couplings. Outcomes may include local block, collision, phase reset, or termination. Do not promise that every tap resets or terminates the rhythm. Use tests to find and document example couplings for specific outcomes if offering guided presets. Formal entrainment, fusion, post-pacing interval and AVRT/AVNRT mechanisms are later extensions requiring additional model validation.

**Protocol E: negative controls.** With all ERPs equal to 220 ms, a single stimulus still extinguishes and the S1/S2 protocol does not obtain the same sustained asymmetric induction. Increase all ERPs beyond the 480 ms loop time and verify that an externally seeded unidirectional wave cannot re-excite its starting node after one revolution. Do not create a public control that fabricates a circulating activation stream; a test-only initial condition or explicit direction gating is sufficient for this negative test.

**Visual identity:** An airy toroidal wreath made of multiple extremely fine concentric or gently twisted filaments. Eight luminous structures act as points of interaction. A moving impulse is a sharply defined leading point with a short trailing wake, constrained to the electrical connection. Each lap may leave an artistic afterimage; afterimages do not constitute additional wavefronts. The actual refractory wake appears behind the leading wave. No decorative particle should look like a second propagating impulse.

| S → A | 25 | fixed |
| A → N | 35 | fixed |
| N → H | 65 | decremental: max extra 90 ms, tau 120 ms |
| H → V1 | 25 | fixed |
| H → V2 | 45 | fixed |

All reverse directions disabled in this simplified reference scene. Recovery tail initially 120 ms. The steady pattern should reach V1 and V2 in order after every successful source activation. Start the source at simulation t=0 or after a short explicitly documented introductory delay. The engine—not audio code—schedules future automaticity.

At 800 ms cycle length, the reference nodal extra delay after a steady preceding activation is approximately 0.9 ms (90 × exp(-(800-250)/120)); the exact first beat is fully rested with zero extra delay. Premature stimuli at the atrial node can produce longer N→H intervals or block at N. Agents must establish a reproducible premature stimulus protocol that does not overlap the next intrinsic beat in a confusing way. Example in the first cycle: S activates at 0, A at 25, N at 60. Stimulating A at 275 makes N attempt at 310, exactly its ERP boundary; the N→H delay becomes 155 ms versus the fully rested 65 ms. Use the equality convention from §4. Verify that downstream tissue accepts or blocks as expected; do not conceal blocks to force an attractive melody.

Atrial overdrive pacing and phase reset of S require additional connections or a deliberately defined command. In this feedforward graph, stimulating A does not reset the upstream sinus source. Do not imply retrograde conduction unless enabled and implemented. Wenckebach can be explored after adding validated rate-dependent dynamics; a fixed ERP plus this simple output delay is not sufficient to guarantee authentic progressive AH prolongation and dropped conduction. Label only tested phenomena.

**Visual identity:** A vertically or diagonally oriented branching sculpture, with a soft upper source, finely curved connections and a warmer lower pair. Avoid the outline of a literal heart. At default dilation, branching activations should unfold as a small phrase rather than a single light flash.

### 5.3 Duality — independent voices and phasing

**Purpose:** Two autonomous rhythms coexist, analogous to AV dissociation or independent oscillators, without one being forced to follow the other. It is a musical exploration of counterpoint, not a simulation of all physiology of complete heart block.

Create two disconnected components, each containing an automatic focus and one or two downstream nodes. Starting parameters:

- Component A: focus cycle 720 ms; downstream conduction delays 45 and 85 ms (choose branch or chain explicitly; recommend branch from focus); ERP 180–220 ms.
- Component B: focus cycle 1,030 ms; downstream conduction delays 60 and 110 ms; ERP 240 ms. Initial B phase offset 170 ms.
- Both foci have reset-on-capture automaticity. No links between components by default. Set recovery tails to 120–180 ms.
- Pan A slightly left and B slightly right; keep both audible in mono. Give them complementary pitch registers and timbres.

Tests: each oscillator maintains its cycle length independent of the other; stimulating a node in A never changes B's state; changing A's automatic cycle creates new phase relationships without changing B. If a coupling control is later added, it must create a real directed link with a specified delay and ERP-dependent capture, not gradually force the audio tracks into synchronization. Connection and synchronization experiments are optional after P1.

**Visual identity:** Two partially overlapping but visually distinguishable structures, perhaps interlocking rings or elongated halos. A warm and a cool voice move through independent temporal patterns. Overlapping geometry alone does not indicate electrical conduction.

### 5.4 Initial world defaults and edit ranges

Suggested starting transport factor: **4× slower** than simulated physiological time (user range 1×–8×, discrete steps or continuous). Circulation's 60 ms per edge becomes 240 ms per note onset at 4×; the loop takes 1.92 s. Conduction's 800 ms cycle becomes 3.2 s. Duality's 720/1030 ms cycles become 2.88/4.12 s. These choices make internal relationships audible while leaving room for decay. Audition 3×, 4× and 5× before choosing a final default. Do not change simulated ERP or conduction times when changing playback dilation.

Lab starting edit bounds (synthetic, not medical limits): ERP 50–1,000 ms, conduction delay 1–500 ms, automatic cycle 200–3,000 ms, recovery tail 20–1,000 ms, decrement max extra 0–300 ms, tau 10–1,000 ms. Validate all values. Use smaller ranges or event budgets if required for performance. Present controls in simulated ms, not dilated wall time. Display the two clocks separately when helpful.

## 6. Musical design and synthesis

### 6.1 Creative goal

Make something a person might enjoy listening to with the screen off. The sound should be original, restrained, expressive, and rich enough to reveal the underlying electrical behavior. Musical touchstones are minimalist repetition, phasing, chamber music, and ambient generative composition. These are broad influences, not requests to reproduce any artist's music or use existing copyrighted compositions. All pitches, voicings and synthesized sounds in the prototype must be original or otherwise properly licensed.

The simulation decides **when** and **which region** activates. The musical mapping decides **how that event sounds**. Do not use a hidden metronome, MIDI clip, backing chord progression, tempo-synchronized LFO that introduces unrelated attacks, or stochastic onset offsets. Every intentional pitched attack must have an accepted activation event as its causal origin. A note may excite a resonant texture and reverb; these are tails of the original event, not independent voices arriving on a separate beat grid.

### 6.2 Mapping contract

```ts
type NoteIntent = {
  eventId: string;                // original accepted activation ID
  tMs: number;                    // original simulation onset; never quantized
  pitchHz: number;
  voice: 'felt' | 'pluck' | 'bow' | 'glass';
  gain: number;
  attackSec: number;
  releaseSec: number;
  brightness: number;
  pan: number;
  reverbSend: number;
};

mapActivation(event, worldMusicConfig, palette): NoteIntent | null;
```

Return null only for intentionally inaudible model nodes if that is explicitly configured, or for nonactivation events. For P0 the ring should make every accepted node activation audible. Events for blocked capture and collisions may have very quiet nonpitched textures in a later palette, but **default is silence**. A visual ripple is enough. The renderer must still show all events even if the mixer caps polyphony.

Musical mapping should be deterministic under identical event histories and palette settings. Fixed node pitch is the most intelligible starting point. Use musical variation through electrical state, instrumentation, stereo location and resonance rather than arbitrarily changing notes on each lap.

### 6.3 Proposed tonal vocabulary

Start with a spacious D-centered minor-pentatonic / Dorian-compatible pitch set. Use D, F, G, A, C, optionally E for color after auditioning. Octave placement is more important than exotic tuning. Avoid close-register low-frequency clusters. Keep lower voices sparse and the upper voices gentle, not piercing. Use equal temperament for P0; alternate tunings can be explored later.

Reference ring assignments (deliberate original pitch layout, modifiable after listening):

| Node | Pitch | MIDI | Voice in Chamber | Approximate stereo pan |
|---|---|---:|---|---:|
| R0 | D4 | 62 | Felt | 0.00 |
| R1 | F4 | 65 | Pluck | +0.25 |
| R2 | A4 | 69 | Felt | +0.40 |
| R3 | C5 | 72 | Glass | +0.25 |
| R4 | D5 | 74 | Glass | 0.00 |
| R5 | A4 | 69 | Pluck | -0.25 |
| R6 | G4 | 67 | Felt | -0.40 |
| R7 | F4 | 65 | Bow or pluck | -0.25 |

Counterclockwise reentry then sounds D4–F4–G4–A4–D5–C5–A4–F4, returning to D4. This is a pitch assignment to spatial nodes, not a sequenced melody. A clockwise wave or another topology will produce a different traversal. Feel free to revise the voicing after audio audition, while preserving pitch identity per node and event timing. To avoid identical pitches erasing the separation between R1/R7 and R2/R5, give them distinct timbres or stereo positions. A/B test more differentiated pitch sets if useful.

Example Conduction assignment: S D4, A A4, N F4, H C5, V1 D3, V2 A3. Duality A uses a higher D/F/A cluster, B a lower D/G/C cluster. These are auditionable defaults, not fixed requirements. A/B comparisons should use identical recorded synthetic event streams so musical mapping differences can be isolated.

### 6.4 Electrical memory expressed as sound

Use `recoveryBefore` from each activation (the state just before the accepted event). A rested activation should sound full; a just-recovered activation may sound quieter, softer, or more muted. Suggested mapping:

```text
r = clamp(recoveryBefore, 0, 1)
velocity = baseVelocity × (0.55 + 0.45 × r)
brightness = baseBrightness × (0.55 + 0.45 × smoothstep(r))
release = baseRelease × (0.65 + 0.35 × r)
```

These are deliberately artistic mappings, not assertions that EGM amplitude tracks this recovery variable. Avoid making legal near-ERP activations inaudible. Blocked stimuli produce no normal activation note. Refractoriness is thereby both audible through changes in resonance and visible through changes in luminosity. Preserve a stable timbral identity for each node so the listener can recognize it through these variations.

### 6.5 Four original instrument families

Build a few excellent voices before adding more instruments. The Web Audio primitives can create acoustic-*inspired* timbres; do not call them realistic sampled instruments. Use smooth envelopes and short ramps to avoid clicks. Use deterministic noise buffers or seeded excitation where appropriate. Avoid oscillator allocation for inaudible events.

| Voice | Proposed synthesis | Typical audible envelope (wall time at 4×) |
|---|---|---|
| Felt piano | Fundamental + a few rapidly decaying partials, mild inharmonicity, very soft short filtered hammer-noise transient, low-pass filter | 3–12 ms attack; 0.45–1.1 s decay/release |
| Plucked string | Damped harmonic bank or short noise excitation through a tuned resonator/delay; avoid unstable feedback | 2–8 ms attack; 0.3–0.8 s decay |
| Bowed string | Layered quiet harmonics with gentle spectral evolution, slow attack, restrained vibrato applied continuously rather than rhythmic note retriggers | 35–100 ms attack; 0.7–1.5 s release |
| Glass harmonic | Sine-based resonators with carefully chosen upper partials, softly rounded attack and decay | 10–30 ms attack; 0.5–1.3 s release |

Default accents should not resemble monitor alarms. High pitches and transients should be gentle on headphones. Limit extreme brightness and sub-bass. Noise is an excitation texture, not hiss. Consider a single reusable stereo impulse-response reverb generated locally (seeded decaying noise, filtering, modest predelay), plus subtle stereo panning. Reverb time ~1.5–2.8 s for Chamber, longer for Atmosphere if headroom permits. Avoid an obvious discrete echo, which could be mistaken for another physiological event.

Time scaling changes **onset intervals** and visual travel time. Envelopes are artistic durations in wall seconds; do not automatically multiply every attack and release by the dilation factor, because notes can become unnaturally long. Consider bounded release adaptation (`sqrt(dilation/4)` clamped, for example) only if auditions justify it. The lab should explicitly identify which durations are simulation time and which are audio time.

### 6.6 Palettes as alternative interpretations

| Palette | Design | Timing treatment |
|---|---|---|
| Chamber (default) | Felt, pluck, warm bowed low strings, restrained glass; differentiated voices, clear attacks, subtle reverb | Exact activation onsets |
| Atmosphere | Softer attacks, more sustained resonances, sparse upper harmonics, deeper space, lower dry level | Same activation onsets; envelope may obscure attack perception intentionally |
| Minimalism | Short crystalline resonances, dry-ish mix, clear articulation and repeating pitch motifs, minimal vibrato | Same activation onsets |

Switching palette never resets, advances, or mutates the biological state. Existing notes may decay with their original palette; new activations use the new palette. Use a short gain crossfade if needed. Do not restart a world to change a musical setting. Avoid forcing every activation to change pitches, chords or voices for novelty. The interesting variation should come from the physiology.

### 6.7 Audio engineering requirements

- Use one lazily created AudioContext, resumed only in response to a user gesture. Handle suspended/interrupted contexts gracefully; display a clear enable/resume affordance. Never attempt autoplay with sound before user consent.
- Schedule note starts using AudioContext time, not a callback firing at arbitrary UI frame times. `setTimeout` / `setInterval` can wake a lookahead scheduler, but cannot be the note clock. Use scheduled AudioParam ramps.
- Set conservative per-voice gains and a master volume initially around 25–35%; choose actual gain after listening and offline analysis. Route through a shared compressor and an explicit conservative peak-protection stage if needed; a DynamicsCompressor alone is not a guaranteed brickwall limiter. Avoid distortion in expected worlds. Make mute, volume and pause separate actions.
- Define a bounded polyphony budget (start 32 or 48 active voices including releases, then measure). Prefer releasing the quietest/oldest tail if overloaded rather than losing a new onset. Record any voice stealing in debug diagnostics; do not suppress physiological events.
- Dispose completed oscillator, filter and gain nodes; track all scheduled future sources for transport reset/pause. Reuse reverb, mixer and buffers, not individual one-shot oscillator nodes.
- Use a dry/wet bus, gentle panning, and mono-compatibility tests. Master and palette transitions should be ramped (e.g. 20–80 ms). Silence after a quiescent network should arise naturally as voices decay; no unrelated ambient audio bed.
- Test at 1× and 8× and with rapid repeated input. Measure clipping, peak level, DC offset, discontinuities, stuck voices and CPU load with OfflineAudioContext or equivalent offline signal analysis when possible. Measurements complement but never substitute for human listening.

### 6.8 Audition and iteration process

Produce 15–30 second reproducible examples from Circulation (single impulse, induction and cut), Conduction, and Duality. Give the creator a way to replay identical stimulation protocols across palettes. If feasible, export short locally generated WAV files for review without launching the app; do not let export work delay P0. The project should include notes on what was actually auditioned, by whom, and which aspects remain subjective.

Questions for review: Is the sound compelling after 30 seconds? Can one hear the transition from bidirectional excitation to unidirectional reentry? Does a blocked beat feel like an absence rather than a software failure? Do independent rhythms form interesting counterpoint without becoming grating? Is a sustained loop pleasant enough to invite perturbation? Does the audio still work without visual context?

## 7. Time, transport and synchronization

### 7.1 One time model

Let `D` be playback dilation: `D=4` means 1 simulated ms corresponds to 4 wall-clock ms. With a shared anchor `(simAnchorMs, audioAnchorSec)`:

```text
presentationAudioTime(tSim) = audioAnchorSec + (tSim - simAnchorMs) × D / 1000
presentedSimTime(audioNow) = simAnchorMs + (audioNow - audioAnchorSec) × 1000 / D
```

Use the same mapping for note scheduling and visual state. The visual renderer shows presented simulation time, not necessarily the future time to which the event engine has already advanced for audio scheduling. Keep a small event buffer and/or state snapshots so a visually refractory node is not dimmed prematurely due to a future committed activation. Maintain history for computing visual recovery at presented time, not the engine's latest future state.

### 7.2 Scheduling and input latency

Start with a 20–25 ms scheduler wake interval and a 50–80 ms audio lookahead; profile on target browsers. The engine advances to a horizon slightly ahead of presentation and publishes events to the audio scheduler and visual buffer. Each successful activation has one scheduled onset. Deduplicate by run ID + event ID. Visual animation uses `requestAnimationFrame` and interpolates active transits by `(presentedTime - departure)/(arrival - departure)` along the curve; it never triggers notes.

Real-time user interaction cannot rewrite a future already committed to the audio clock without explicit rollback. Implement a clear policy: show immediate nonphysiologic gesture feedback (small outline ripple), then timestamp the stimulus at the earliest uncommitted simulation instant, with a short scheduler safety margin. It should generally capture or block within approximately 50–100 ms of the input in wall time under normal load. Display actual activation only when its scheduled event is presented. Do not falsely backdate stimuli or play an optimistic note before the engine accepts capture.

If an event is late due to browser throttling or a stalled main thread, do not burst-play a backlog. Pause and re-anchor or skip presentation of stale events with an explicit diagnostic; never silently rewrite the physiological event history. Target <40 ms visual/audio alignment error during normal foreground operation; browser/audio output latency may be device dependent. Where supported, use an audio output timestamp or calibrated offset to better align visible and audible events. Measure, don't claim sample-accurate perceived alignment on every device.

### 7.3 Transport state machine

States: `idle` (await sound permission), `running`, `paused`, `faulted`. Optional `muted` is an independent mixer state. In idle, show a beautiful static or gently breathing visual preview that does not pretend to represent running activation; Begin starts simulation and audio together. If silent exploration before audio permission is supported, define how the clock anchors upon enabling sound; simpler P0 is Begin first.

- **Begin:** Create/resume audio context, establish anchors, initialize world, start scheduler and render loop. If audio fails, offer a silent mode with a monotonic performance clock and clearly indicated sound-disabled state.
- **Pause:** Freeze model presentation, stop scheduler, cancel future notes/transits from the presentation buffer as appropriate, fade audio tails. Because the engine may already be ahead of the visible cursor, either pause at the committed horizon (short bounded delay, allow its scheduled presentation to complete) or restore an engine snapshot at the visible cutoff. The recommended P0 policy is to pause at the committed horizon to avoid rollback; label the control state promptly and never visibly jump through unseen events. Do not discard valid future engine events without a matching state reset or rewind.
- **Resume:** Re-anchor at the frozen simulation time; do not replay past activations or restart automatic phases. Any remaining not-yet-due engine events run normally.
- **Reset / scene change:** Invalidate run ID, cancel queued audio notes, fade existing sound briefly, clear event buffers and histories, load clean world state. Avoid old notes from a previous scene sounding in the new one.
- **Change dilation:** At a safe committed boundary, re-anchor using continuous simulation time and new D. Maintain physiological state and pending conduction timestamps. New note times and visual travel speed change together. Do not rescale simulated ERP or pending delays, do not quantize, and do not abruptly play canceled events. Existing sounding tails can retain their envelope.
- **Background tab / mobile interruption:** Prefer automatic pause on document visibility loss or suspended audio context, with explicit resume on return; avoid draining batteries or accumulating a backlog. Keep model state. Test browser back/forward and tab suspension where practical.
- **Mute:** Change mixer gain without changing simulation speed, audio mapping or node behavior. Unmute should reveal current activity, not a backlog.

Document how any lookahead boundary is handled. In transport tests, vary the frame cadence and verify no note onset duplication, invalid backward timestamps, lost state, or stale events after reset.

## 8. Visual art direction and renderer implementation

### 8.1 Design system

The aesthetic should be closer to a gallery installation, an astronomical instrument, or an intimate kinetic sculpture than a traditional web app. Use editorial restraint, not decorative maximalism.

Suggested palette (tune on actual displays): background `#080C13`, deep atmosphere `#111D2B`, warm filament `#C8A878`, warm core `#FFF1D1`, cool filament `#83A9C8`, cool core `#D9F1FF`, primary text `#E3DED5`, secondary text `#9CA9B8`. Use color sparingly; avoid saturated greens, reds and purple gradients. Blocked state should be recognizable by shape and brightness as well as color. Fonts: system sans-serif for tiny controls, optional system serif or restrained letterspaced wordmark for title. No external font requests. Keep text contrast accessible even when the artwork itself is deliberately dim.

Use a centered canvas with wide margins and responsive scene framing. The artwork is the focal point. In Circulation, let the ring occupy roughly 55–70% of the shorter available canvas dimension, adjusting for the bottom control strip and mobile. Avoid a visually dead empty screen before Begin. Keep node hit targets much larger than visible cores (minimum ~44 CSS px when possible). Render at device pixel ratio, cap backing resolution reasonably (e.g. DPR 2 or 2.5) to avoid mobile GPU/CPU stress.

### 8.2 Visual semantic language

| Biological state/event | Required visual expression |
|---|---|
| Rested / excitable | Small stable luminous core, fine halo, receptive visual state |
| Accepted activation | Brief white-warm or cool bloom at exact event time, localized expanding ring, corresponding note |
| Propagation | Bright moving leading point following the correct link, finite tapering trail; direction and arrival observable |
| Refractory | After flash, dim or contracted core; muted halo, distinctly unavailable |
| Relative artistic recovery | Gradual return of halo/luminosity in proportion to model recovery |
| Block | Brief attenuating ripple at attempted node, no continuing outgoing wave from that blocked attempt, no normal note |
| Collision | Two points converge and disappear in a small soft dissolution at actual model collision location; no fictitious outgoing wave |
| Link cut | Visible gap, dimmed or separated filament; active transit ends if on that link |
| Recent activity | Fading afterimages or dust that cannot be mistaken for new impulses |
| User input awaiting scheduling | Subtle neutral outline/ripple, visually different from an accepted activation |

Do not use node brightness alone to determine capture. Activation flash is a separate envelope from underlying recovery. Color primarily identifies voices/regions; it should not imply membrane potential quantitatively. Provide a simple optional legend in lab. Reduced-motion mode can use short flashes and stationary state changes rather than trails or oscillating camera effects.

### 8.3 Rendering layers

Suggested back-to-front order:

1. Near-black background with extremely subtle stationary radial gradients or grain. Avoid distracting drifting starfields. If grain is used, generate a small local texture and cache it.
2. Decorative topology echoes: multiple faint concentric or parallel threads that make the structure sculptural. They are not additional conduction pathways; use lower contrast and distinct appearance from the true path.
3. Actual electrically connected paths (curves with a shared normalized coordinate system, cached paths and geometry). Disabled links visibly split or dim. For non-directed bidirectional paths, no permanent arrowhead necessary; moving wavefront conveys direction. Optional lab direction arrows.
4. Propagation and afterimages. Compute progress from event timestamps. Use arc-length approximation for Bézier paths so a constant conduction velocity looks reasonably constant spatially; visual geometry is not a physical distance measurement. Opposite directions share the same underlying path parameterization.
5. Node state halo and core. Apply restrained radial gradients, thin rings, flash amplitude, and subtle stationary details. No continuous pulsing that looks like physiological activation unless an actual event occurred.
6. Event ripples, collisions, cut markers, and gesture feedback. Keep each localized and time-limited.
7. Semantic DOM overlays: title, scene navigation, hover/focus node labels, controls, optional inspector. Canvas itself may be `aria-hidden` if a parallel accessible node/connection control list exists.

Performance: precompute paths, avoid allocating many gradients or objects every frame, cache static layers, bound visual particle counts, maintain a time-pruned history. Use `requestAnimationFrame`, pause when hidden, and degrade decorative effects before losing event visibility. Test high-DPI mobile. A target of 60 fps is aspirational; ensure responsive 30 fps fallback and stable audio even when visuals slow.

The guided protocol control should have an evocative label (e.g. **Find a circulating rhythm**) with an accessible explanatory label (S1/S2 induction on a rested ring). Do not automatically overwrite user experiments without making reset effects clear.

### 8.5 Later visual modes

**Score:** a time-based multi-channel representation of model activations, resembling EP traces and musical staves. Horizontal scale is simulated time; optional dilated playback cursor. Build synthetic EGMs from deterministic kernels aligned to accepted activation times, with clearly labeled synthetic morphology. A node activation is not a real measured intracardiac electrogram. Include optional note heads and intervals; no fake AF noise or fabricated patient data. P1 lab can show a simple raster timeline instead of the full artistic score.

**Orbit:** phase relationships of automatic voices or circulating waves represented by orbital trajectories and trails. Derive phase from actual events, not decorative periodic clocks. **Field:** a future reaction-diffusion or excitable cellular lattice; this is a different physiological model, requiring separate numerical validation before advertising fibrillation. Do not render fictitious continuous tissue propagation from an unrelated decorative shader and call it a real simulated wave.

## 9. Interaction design and laboratory

### 9.1 Main interactions

- Tap/click a node to attempt a suprathreshold local stimulus. Also support keyboard activation via accessible node buttons (Enter/Space); offer a focus indicator and node labels in an accessibility/lab layer. Use pointer events and touch-action settings that do not prevent ordinary scrolling outside the canvas. Avoid accidental browser zoom/scroll when performing deliberate gestures.
- Pause/resume, mute/unmute, volume, world selection, time dilation, and palette selection. Controls are visible enough to discover without making the artwork look like a dashboard. Preferences can persist locally but model state need not persist across reload.
- Circulation guide: show a one-gesture action for the known S1/S2 induction protocol. In P0 it may explicitly reset the ring to a rested state. Explain briefly that two timed impulses are introduced; all subsequent activity is simulated. Offer a one-impulse reference action and a reset. After induction, allow the user to disable a selected connection, watch termination, and restore it.
- Performer mode can optionally provide hold-to-pace with cycle length in simulated ms; use a clearly armed mode, bounded pacing rate, and cancellation on pointerup, pointercancel, blur, pause or scene change. Manual tapping remains the default.
- Advanced edits (P2): draw a connection, edit direction/delay, add nodes, alter ERP and automaticity, cut/restore. Do not silently make screen distance alter conduction velocity unless the user deliberately chooses that mapping. If geometry and conduction delay are coupled later, explain the rule.

### 9.2 Laboratory inspector (P1)

Hidden by default; one compact control opens a drawer or overlay. It should be useful to an electrophysiologist and a developer, not only decorative. Include:

| Panel | Content |
|---|---|

### 9.3 Accessibility and failure states

The app must be meaningful when sound is disabled and usable without a mouse. ## 12. Creative review scorecard

This is intentionally subjective where artistry is involved. Use it as a review aid, not a mathematical substitute for taste. Score 1–5 and record concrete observations. Scientific integrity and basic usability are hard gates regardless of artistic score.

| Dimension | Review question |
|---|---|
| Musicality | Would I listen for a minute with my eyes closed? Are timbres nuanced, dynamics restrained, and the looping motif pleasant? |
| Physiological legibility | Can I distinguish sequential conduction, block, recovery, reentry and dissociation by the relationships in time? |

## Appendix B. Terminology for collaborators

| Term | Meaning here |
|---|---|
| Activation | Successful excitation of an element, causing a refractory period and eligible outgoing conduction |
| ERP | Effective refractory period, the interval after activation during which this toy model rejects another activation |
| Capture | A stimulus successfully activates its target node |
| Conduction | A propagation event traveling between excitable elements with finite delay |
| Block | Failed propagation/activation due to refractory state or disabled conduction |
| Reentry | A wave travels through a closed path and re-excites tissue that has recovered, sustaining activity |
| Unidirectional block | An impulse fails to propagate in one direction but succeeds in another, allowing a potential reentrant wave |
| S1/S2 | Conditioning and premature stimuli separated by a specified coupling interval |
| TCL | Tachycardia cycle length; here, time between successive activations at a reference node during stable circulation |
| Decremental conduction | Longer conduction time at shorter recovery intervals, as represented by the toy model |
| Entrainment | Capture/reset of an ongoing rhythm by pacing, with more specific criteria in clinical EP; formal demonstration deferred |
| Automaticity | Autonomous generation of activation attempts by a focus |
| Dissociation | Independent rhythms without obligatory temporal coupling |
| EGM | Electrogram; derived traces in this project are synthetic representations, not recordings |
| Time dilation | Uniform slowing of presentation relative to simulated physiology |
| Palette | A musical interpretation of the same event stream, not a change in physiology |
